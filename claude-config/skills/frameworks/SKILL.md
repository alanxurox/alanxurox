# Decision & Strategy Frameworks

## Babson ET&A (Entrepreneurial Thought & Action)

**Core principle:** Act → Learn → Build → Repeat

### The Five Principles

#### 1. Start with Means at Hand
Don't plan for resources you wish you had. Map what you actually have:
- **Who am I?** (skills, knowledge, position)
- **What do I know?** (domain expertise, technical skills)
- **Whom do I know?** (network, relationships, allies)

#### 2. Affordable Loss
Ask "What can I lose?" not "What might I gain?"
- Set explicit limits: time, money, social capital
- If you can afford to lose it, experiment freely
- Prevents over-investment in unvalidated ideas

#### 3. Leverage Contingencies
When unexpected things happen, treat them as data:
- Surprise = information about reality
- Pivot based on what you learn
- Plans are hypotheses, not commitments

#### 4. Build Networks Through Action
Don't network in the abstract. Engage through work:
- Reach out with specific asks
- Offer concrete value in return
- Relationships form through collaboration, not events

#### 5. Control What You Can
Focus on actions within your control:
- You can't control outcomes
- You can control efforts, experiments, iterations
- Make progress through action, not prediction

### ET&A Sprint Template

```markdown
## Sprint [N]: [Date Range]

**Act:**
- [ ] Specific action 1
- [ ] Specific action 2

**Learn:** What did we discover?

**Build:** What do we adjust based on learning?

**Repeat:** Next sprint actions
```

## Founder's Mentality (Bain & Company)

**Core principle:** Think like an insurgent founder, not a corporate manager

### Three Elements

#### 1. Insurgent Mission
- **Clear enemy:** What are you fighting against?
- **Spiky point of view:** What do you believe that others don't?
- **Purpose beyond profit:** Why does this matter?

Example: "First-time correct HTML from AI — no more guessing CSS classes"
- Enemy: Rework cycles, wrong AI output
- Belief: Skills solve the context problem
- Purpose: Make content dev faster and less frustrating

#### 2. Front-Line Obsession
- Stay close to the people doing the work
- Shadow, don't survey
- Build for real problems, not imagined ones

**Tactics:**
- Watch users work (don't just ask what they need)
- Test with real placements, not demos
- Iterate based on actual failures

#### 3. Owner's Mindset
- Act like you own the outcome
- Bias toward action over permission
- Don't wait for perfect conditions

**Not:** "Should we get approval for this?"
**Yes:** "I'm doing this. Here's what I learned."

### Founder's Mentality Anti-Patterns

| Corporate Behavior | Founder Behavior |
|-------------------|------------------|
| Wait for consensus | Act, then iterate |
| Design by committee | Ship and learn |
| Protect territory | Solve the problem |
| Manage up | Build down (for users) |
| Presentation theater | Working demos |

## Competitive Analysis Framework

**Core principle:** Understand landscape to find gaps, not to copy.

### Quick Competitive Scan

| Question | How to Answer |
|----------|---------------|
| Who else solves this? | Glean search, web search, ask users |
| What do they do well? | Use their product, read reviews |
| Where do they fail? | Support forums, social complaints, 1-star reviews |
| What's our spiky difference? | The thing we believe that they don't |

### Porter's Five Forces (Simplified)

| Force | Question |
|-------|----------|
| Rivals | How crowded? Who's winning? |
| New entrants | How hard to copy us? |
| Substitutes | What else solves the same job? |
| Buyer power | Can users easily switch? |
| Supplier power | Who do we depend on? |

### Output: Positioning Statement

```
For [target user] who [pain point],
[Product] is a [category]
that [key benefit].
Unlike [competitor],
we [key differentiator].
```

## Social Sentiment & Pain Point Analysis

**Core principle:** Users tell you what to build in their complaints.

### Where to Look

| Source | What to Find |
|--------|--------------|
| Twitter/X | Real-time frustration, unfiltered |
| Reddit | Detailed complaints, workarounds |
| G2/Capterra reviews | Structured feedback, competitor weaknesses |
| Support tickets (Glean) | Internal pain points |
| Slack channels | Team friction, process gaps |

### Sentiment Signals

| Signal | Meaning |
|--------|---------|
| "I wish..." | Unmet need |
| "Why can't..." | Friction point |
| "I had to..." | Workaround = opportunity |
| "Every time I..." | Repeated pain |
| "Finally switched to..." | Competitor win (study why) |

### Pain Point → Project Pipeline

1. **Collect** pain points (Glean, social, forums)
2. **Cluster** by theme
3. **Score** by frequency × severity
4. **Validate** with 2-3 user conversations
5. **Propose** as project if score > threshold

## Decision Framework: When to Use Which

| Situation | Framework | Why |
|-----------|-----------|-----|
| Starting new initiative | ET&A (Means Mapping) | Know what you have before planning |
| Feeling blocked/waiting | Founder's Mentality (Owner's Mindset) | Action over permission |
| Unclear what users need | Front-Line Obsession | Shadow, don't assume |
| Over-planning | ET&A (Act → Learn) | Experiment beats speculation |
| Scope creep | Affordable Loss | Set explicit limits |
| Network building | ET&A (Build through action) | Reach out with specific value |
| Finding opportunities | Social Sentiment Analysis | Pain points = projects |
| Positioning product | Competitive Analysis | Find gaps, don't copy |
| Autonomous project discovery | Sentiment + Competitive | Cluster pain → validate → propose |

## Quick Reference: Questions to Ask

### Before Starting
- What do I actually have? (means mapping)
- What can I afford to lose? (affordable loss)
- What's my insurgent mission? (clear enemy)

### When Stuck
- Am I waiting for permission I don't need? (owner's mindset)
- Have I actually talked to users? (front-line obsession)
- What small action could I take right now? (act → learn)

### After Action
- What surprised me? (leverage contingencies)
- Who could I engage based on this? (build networks)
- What do I adjust for next iteration? (build → repeat)
